## 1. Google designs private, persistent memory for cloud AI

![Market State Lab abstract AI and computing category illustration](https://raw.githubusercontent.com/rsh63/market-state-lab/main/story-1-ai.png)

*Credit: original Market State Lab category illustration; not an event photograph.*

**Fact:** Google DeepMind described persistent, cross-device AI memory using isolated computing environments, per-user encrypted databases, and decryption keys held on personal devices. Its September 23 announcement also describes a public software-transparency record and independent audits. [Google DeepMind](https://deepmind.google/blog/advancing-private-ai-compute-with-secure-server-side-memory/)

**Inference:** Persistent memory makes key management, retention, deletion, and access boundaries part of an agent's core architecture.

**Uncertainty:** These are vendor design claims, not an independent validation of every deployment. Availability and operational effectiveness remain to be established.

**Why it matters:** Give MATLAB-connected agents explicit retention and deletion controls. Keep secrets out of model memory and separate remembered user information from training and evaluation datasets.

## 2. Treasury basis positions shrink as arbitrage returns compress

![Market State Lab abstract quantitative-finance and market-structure category illustration](https://raw.githubusercontent.com/rsh63/market-state-lab/main/story-2-quant.png)

*Credit: original Market State Lab category illustration; not an event photograph.*

**Fact:** Morgan Stanley estimates leveraged Treasury basis positions have fallen 20% this year to $1.2 trillion, chiefly in two- and five-year contracts, as arbitrage opportunities compress. [Reuters, September 24](https://www.reuters.com/legal/transactional/hedge-funds-sour-basis-trade-treasury-selloff-continues-2026-09-24/)

**Inference:** Smaller positions need not mean forced deleveraging; expected returns can simply deteriorate.

**Uncertainty:** These are estimates, not a complete view of leverage or funding stress.

**Why it matters:** Model repo costs, haircuts, margin, cheapest-to-deliver selection, and roll exposure separately. A basis strategy is not merely a directional Treasury trade.

### Execution implications

- Separate pre-release, post-release, opening-auction, and first-30-minute regimes. Weekly claims normally arrive Thursday at 7:30 a.m. CT; no current release was available at the cutoff. [Labor Department release schedule](https://oui.doleta.gov/unemploy/claims_arch.asp)
- Require fresh spread, depth, quote-age, and auction-imbalance checks. Do not import yesterday's option surface unchanged.
- Use auction-aware limits, participation caps, cancellation controls, and realized-slippage kill switches; reduce activity when depth is unverified.
- Rebuild SPY/QQQ implied volatility, skew, open interest, and strike liquidity after the release and open. Same-day expiry can concentrate hedging; dealer gamma sign and magnitude were not verified.
- Reject stale, crossed, zero-bid, one-sided, or thin options markets. Model repo, margin, and Treasury basis independently of outright yield moves.

### DRL Improvements for the MATLAB System

1. Add funding-publication lag, missing-data flags, yield changes, quote age, session, and event phase. Use only information available at each decision timestamp.
2. Enforce drawdown, concentration, leverage, liquidity, and daily-loss constraints outside the reward. Penalize downside tails and implementation shortfall inside it.
3. Randomize funding and margin shocks, depth collapses, spreads, partial fills, latency, and nonlinear impact; score robustness separately by regime.
4. Use purged, embargoed walk-forward evaluation with frozen baselines, multiple seeds, and untouched event blocks. Calibrate costs on training data only.

### Model hygiene

Control leakage, survivorship and look-ahead bias, corporate actions, first-available timestamps, stale options quotes, and multiple testing. Separate regular and overnight sessions. Calibrate out of sample, retain rejected trials, and monitor feature, probability, policy, transaction-cost, and regime drift.

### MATLAB optimization

- Align data with `timetable`, `retime`, and `synchronize` using first-available timestamps; preserve missingness and staleness rather than backfilling future information.
- Vectorize rolling features, preallocate buffers, and profile environment steps before parallelizing.
- Run parallel `bayesopt` across independent purged folds with reproducible random streams and multiple seeds.
- Use GPUs for sufficiently large neural-network batches; separate environment, execution-cost, constraints, and agent modules.
